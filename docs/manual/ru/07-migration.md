# 7. Перенос из Zaprite и Request Finance

Если раньше вы пользовались Zaprite или Request Finance, вы можете перенести своих клиентов и историю счетов, чтобы Sealbill стал единственным местом, где можно найти всё. Пошаговая процедура, включая то, как получить данные из каждого сервиса, описана в [docs/migration.md](../../migration.md). Эта глава говорит, что импорт делает, а чего нет.

## Принцип: история, а не живые счета

**Каждый перенесённый счёт записывается как уже оплаченный.** Ничто из того, что было открыто в другом месте, не подлежит оплате в Sealbill, поэтому клиент никогда не заплатит дважды, и никому ничего не отправляется. Каждый счёт сохраняет исходный номер, дату выставления, валюту, позиции, название и примечание внизу.

- Каждый получает ровно один платёж: способ *Recorded by hand*, подтверждённый, на всю сумму, с датой оплаты из источника (или датой выставления). К платежу прилагается заметка с названием источника и исходным номером.
- Статус источника (`COMPLETE`, `PAID`, `OVERPAID`, `PROCESSING`, `UNDERPAID`, `awaitingPayment` и т. д.) сохраняется для сотрудников и никогда не показывается клиенту. В CSV счетов есть столбец **migrated_from** (например, `zaprite:COMPLETE`), чтобы бухгалтерия могла отличить платёж, который клиент действительно совершил, от счёта, который вы объявили оплаченным.
- Перенесённый счёт **доступен только для чтения**: из него нельзя ничего отправить, оплатить, отменить, аннулировать, перевыпустить, оформить котировкой или удалить — ни сотрудникам, ни через API. Его страница сообщает, откуда он, и ссылается на оригинал, пока существует тот аккаунт.
- **Ничего не срабатывает.** Импорт не отправляет письма, не порождает вебхуков, не создаёт котировок и ссылок и не сдвигает следующий номер организации.

## Что происходит с контактами

Контакты **объединяются по адресу электронной почты внутри организации** (без учёта регистра): один человек, встречающийся и в Zaprite, и в Request Finance, становится одним контактом, дополненным из того источника, где есть данные. Контакт без почты сохраняется и привязывается только к счетам, которые на него указывают; по имени он никогда не объединяется. Записи из Zaprite и Request Finance попадают в названную вами организацию; эмитент для США отклоняет записи из Zaprite, если вы не добавите `--allow-us-issuer`.

## Номера

Собственный номер источника сохраняется. Если такой номер в организации уже есть (и Zaprite, и Request Finance нумеровали просто), у того, что приходит вторым, в конце добавляется метка источника: `591-RF` (или `-Z`). Пробный запуск перечисляет каждую коллизию, прежде чем что-либо записывается. Номер, который по форме совпадает с собственной нумерацией организации и не меньше её следующего номера, отклоняется — решайте вручную.

## Запуск импорта

Импортёр читает со стандартного ввода **JSON по строкам** (newline-delimited): одна запись `contact` или `invoice` в строке.

```json
{"type": "contact", "source_id": "c1", "email": "old.client@example.com", "legal_name": "Old Client Ltd.", "address": {"line1": "1 Archive Road", "city": "Brno", "zip": "602 00", "country": "CZ"}}
{"type": "invoice", "source_id": "449", "number": "449", "kind": "invoice", "contact_source_id": "c1", "currency": "EUR", "issue_date": "2025-04-01", "paid_date": "2025-04-03", "due_days": 14, "title": "Consulting", "lines": [{"name": "Consulting", "quantity": "1", "unit_price_minor": 133700}], "total_minor": 133700, "source_status": "COMPLETE", "source_url": "https://app.zaprite.com/example/449"}
```

- Суммы указываются в minor units; `total_minor` должно совпадать с тем, что вычисляют позиции (налог и скидки по позициям переносятся), иначе запись отклоняется.
- У `address` контакта ровно ключи `line1`, `line2`, `city`, `zip`, `state` и `country` (двухбуквенный код). Любой другой ключ отклоняется поимённо, чтобы поле никогда не потерялось незаметно.
- Каждый счёт записывается в конечном состоянии в собственной транзакции.

```bash
manage.py import_invoices --source zaprite --org example-studio --dry-run < export.ndjson
manage.py import_invoices --source zaprite --org example-studio           < export.ndjson
```

Хранилище должно быть разблокировано. **Всегда сначала запускайте `--dry-run`**: он делает всё, откатывает и выводит только количества:

```text
DRY RUN: nothing was written (source zaprite, org example-studio)
contacts: new 1, merged 0, without e-mail 0, skipped (already imported) 0
invoices invoice EUR: 1
invoices payment_request USD: 1
total EUR: 133700 minor units
total USD: 5000 minor units
skipped, already imported: 0
source status COMPLETE: 1
source status PAID: 1
number collisions: 0
refused lines: 1
  line 4 zaprite:bad: the lines do not add up to total_minor
```

- Вывод никогда не содержит имени, адреса, электронной почты или суммы по клиенту. Отклонённая или пропущенная запись называется `<source>:<source_id>` и номером строки, чтобы вы могли найти её в выгрузке.
- **Его можно запустить повторно.** Счёт или контакт, чей исходный id уже импортирован, пропускается, так что прерванный на полпути запуск просто повторяют. Два одновременных запуска отклоняются.
- Записи черновиков, отменённых и отклонённых счетов из Request Finance пропускаются: никто их не был должен.
- В журнале аудита одна запись на запуск только с количествами и одна на счёт — с источником и его id.
- `--btc-check id,id` выводит для названных исходных id сумму в сатоши и URL источника, чтобы сверить биткоин-счёт с бухгалтерией.

После импорта проверьте один-два перенесённых счёта на странице **Invoices** и скачайте CSV счетов за период (глава 8); итоги по валютам, выведенные пробным запуском, должны совпадать с цифрами источника.
