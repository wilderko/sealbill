# 9. API вкратце

Всё, что страницы для сотрудников делают со счетами, может сделать другая программа через JSON API по HTTPS, базовый URL `https://<ваш хост>/api/v1`. Ваша собственная установка отдаёт полную, всегда актуальную документацию:

| Адрес | Что это |
|---|---|
| `/api/v1/docs` | Документация для людей (интерактивная страница OpenAPI). |
| `/api/v1/schema` | Схема OpenAPI 3.1 для генерации клиента. |
| `/llms.txt` | Справочник простым текстом для программ и ИИ-агентов: каждая конечная точка, каждая ошибка, события вебхуков и способ их проверки. |

Эта глава — лишь кратчайший путь внутрь. Остальное читайте в этих трёх источниках и в README: [Integrating another system through the API](../../../README.md#integrating-another-system-through-the-api).

## Аутентификация

Создайте токен для одной организации (глава 2 или `manage.py create_api_token --org <slug> --name <name> --scopes read,invoices:write`) и отправляйте его как bearer-токен:

```bash
curl -H "Authorization: Bearer $TOKEN" https://pay.example.org/api/v1/me
# {"organization":"example-studio","token":"shop-integration","scopes":["read","invoices:write"]}
```

Неверный, отсутствующий или отозванный токен даёт 401, недостающий scope — 403, более 120 запросов в минуту на токен — 429. Пока хранилище запечатано, любой вызов отвечает 503 `{"error": "vault_sealed"}`; повторите позже. Ошибки всегда имеют вид `{"error": "<code>", "detail": …}`.

## Создание и отправка счёта

Суммы — **целые числа в minor units** (центах), количества — десятичные строки, ставки налога и скидки — базисные пункты (2000 — это 20 %). При создании передавайте `Idempotency-Key`, чтобы повтор после тайм-аута не создал второй счёт:

```bash
curl -X POST https://pay.example.org/api/v1/invoices \
  -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: order-1042" -H "Content-Type: application/json" \
  -d '{"contact": {"email": "anna@example.com"}, "currency": "EUR",
       "lines": [{"name": "Consulting", "quantity": "1", "unit_price_minor": 50000}]}'
```

Это создаёт **черновик**: деньги не двигаются, ничего не отправляется. Затем отправьте его:

```bash
curl -X POST https://pay.example.org/api/v1/invoices/14/send \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"email_client": false}'
```

Ответ содержит номер и **один раз** `view_url` и `pay_url`. `email_client: false` пропускает только письмо со счётом; `client_letters: false` означает, что ни одно письмо об этом счёте никогда не уйдёт клиенту из Sealbill (счёт, квитанции, новые ссылки и напоминание через 30 дней) — для магазина, который сам пишет своим покупателям. Если обе опции требуют письма, они противоречат друг другу.

`GET /api/v1/payment-methods?currency=EUR&contact_email=client@example.com` сообщает, какая организация выставила бы счёт (с применением правила для США) и какие способы она предложила бы. Счёт показывает `amount_paid_minor` и `balance_due_minor`, а `GET /api/v1/payments?invoice=<id>` перечисляет его платежи.

## Scopes с первого взгляда

| Scope | Типичное применение |
|---|---|
| `read` | отчётность, сверка, экспорт |
| `invoices:write` | магазин или CRM, выставляющие счета; контакты, ключи, платёжные ссылки |
| `payments:confirm` | бэк-офисный инструмент, который подтверждает, отклоняет, отменяет или назначает платежи. Меняет состояние денег. |
| `admin` | всё перечисленное плюс вебхуки |

Некоторые действия **только для человека**, и любой токен, даже `admin`, получает `409 needs_person`: запись ручного платежа и подтверждение или назначение платежа, который ждёт человека.

## Вебхуки

Вместо опроса зарегистрируйте конечную точку (глава 2 или `POST /api/v1/webhooks` с токеном `admin`). Каждая доставка — подписанный `POST`; прежде чем ему доверять, проверьте HMAC-SHA256 необработанного тела вашим секретом в `X-Pay-Signature`, ответьте 2xx в течение 10 секунд и устраняйте дубликаты по `X-Pay-Event-Id`. В `/llms.txt` есть события и пример проверки.

## Для ИИ-агентов: сервер MCP

`mcp_server/` позволяет ИИ-агенту работать с API через Model Context Protocol, с восемью инструментами и **без** права подтверждать платежи, аннулировать счета или управлять вебхуками. Выпускайте его токен только с `read` и `invoices:write`. Он описан в README: [MCP server](../../../README.md#mcp-server).
